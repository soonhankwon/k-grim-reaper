# 개발 진행 기록

## 2026-10-27 — 0.10.0 유품 사건 선택

첫 보상 뒤 기존 동경을 챙기거나 두는 사건을 추가했다. 챙길 때 보따리 공간을 확보해 배치·확정하며, 두 번째 승리 때 동경이 실제 보따리에 있으면 다른 대사와 최대 4 체력 회복이 발생한다. 보관대에 두거나 선택하지 않은 경우 다른 반응으로 이어진다. 두 선택 모두 기존 경로·보상으로 돌아온다. [유품 사건](event-flow.md)

사건 텍스트·아이템 참조·회복량은 콘텐츠 스키마 4와 `events.csv`, 템플릿 events 탭에 둔다. 판정은 복사본에서 수행하고 저장 성공 뒤 커밋·Action Queue로 재생한다. 이전 0.9 저장은 기존 콘텐츠가 같으면 사건 위치를 되돌리지 않고 이전한다. 아이템·적·그래픽의 종류는 늘리지 않았다.

검증: 콘텐츠 53·규칙 99·연쇄 22·재생 24·보상 61·저장 123·경로 50·사건 84, 총 516개가 통과했다. 사건 UI의 3개 화면 크기·임시 배치 및 연출 중 종료·저장 복구, 0.9 원본 백업, release PCK 로딩과 별도 프로세스 저장·복원도 통과했다. 템플릿에서 계산한 CSV는 Godot 로더와 일치한다. 실제 Windows 실행과 외부 플레이 테스트는 미검증이다.

## 2026-10-27 — 0.9.0 첫 인도 사연

신입 차사가 이름이 번진 명부와 꺼지지 않은 등불의 흔적을 따라가는 짧은 창작 사연을 추가했다. 현재 사연 카드와 스크롤 가능한 기록은 표시 스냅샷의 진행에 따라 단서를 공개한다. 적 순서를 바꿔도 길목 진행 순서를 따르며 인도 완료 전에는 결말을 공개하지 않는다. 사연 화면은 상태·저장을 바꾸지 않고 0.8 저장을 그대로 읽는다. [사연 데이터와 표시](story-flow.md)

사연 문구를 별도 `story.csv`에서 검증·JSON 변환하며 실패 시 기존 데이터를 보존한다. 기존 아이템·적·이미지 수와 전투 밸런스는 그대로다. `bash scripts/export-windows.sh`에서 규칙 432개, 기존 UI와 사연 UI, 잘못된 사연 CSV 보존, release PCK 로딩 및 두 프로세스 저장·복원 검사가 통과했다. 실제 렌더링 화면은 `build/story-screen.png`다. 사연 선택지·임무 유품·사건·장터는 아직 없으며 Windows 실기기와 외부 플레이어의 이야기 이해도도 미검증이다.

## 2026-10-27 — 0.8.0 첫 플레이 길잡이

배치·전투·보상·승리·갈림길·패배·완료에 따라 안내가 바뀌는 비차단 길잡이를 추가했다. 물건 상세가 표시될 때는 상세가 우선하고, 상단 버튼으로 길잡이를 숨기거나 다시 열 수 있다. 안내는 표시 스냅샷만 읽으며 진행·저장·전투 데이터는 변경하지 않는다. 갈림길에서 잘못 호출된 기본 행동이 새 런을 시작하지 않도록 제한했다. [첫 플레이 길잡이](first-play-guide.md)

단계 전환과 승리 전 표시 시점, 안내 열기·닫기와 상세 우선순위, 3개 창 크기, 안내 조작 시 저장 불변, 경로 선택 후 재실행을 자동 확인한다. 실제 Godot 렌더링의 첫 화면은 `build/guide-screen.png`에서 확인했다. `bash scripts/export-windows.sh`의 전체 규칙 432개, 길잡이 포함 UI 검사, release PCK 로딩과 별도 프로세스 저장·복원 검사가 통과했다. Windows 실기기 및 외부 플레이어가 도움 없이 이해하는지 여부는 미검증이다.

## 2026-10-27 — 0.7.0 경로 선택과 레트로 픽셀 시안

첫 보상 후 두 갈래 중 하나를 고르면 기존 적 세 명의 방문 순서가 달라진다. 다음 적의 체력과 첫 행동을 표시하며 두 보상은 경로 단계에 따라 지급한다. 갈림길 선택은 순수 판정 → 저장 → 커밋 → Action Queue 재생을 따른다. `routes.csv`, 콘텐츠 스키마 3과 밸런싱 템플릿의 routes 탭을 추가했다. [경로 흐름](route-flow.md)

배경·기존 4명 캐릭터·기존 12개 아이템에 굵은 레트로 픽셀풍의 AI 생성 정적 시안을 적용했다. 실제 게임 화면을 참고했지만 그 이미지 자원은 포함하지 않았다. [아트 참고](art-reference.md) 및 `build/retro-game-screen.png`. 최종 픽셀 규격·수작업·애니메이션은 미완성이다.

0.6 저장은 기존 콘텐츠가 일치하는 경우에만 원래 길목 순서를 유지해 이전한다. 기존 데이터가 바뀐 저장은 자동 혼합하지 않는다. 전체 검증에서 콘텐츠 53개·규칙 99개·연쇄 22개·재생 24개·보상 61개·저장 123개·경로 50개, 총 432개가 통과했다. 경로별 진행·유효하지 않은 선택·저장 충돌·이전과 3개 화면 크기의 UI, release PCK의 콘텐츠·저장 복원 검사도 통과했다. Windows 실기기·외부 플레이 테스트, 스토리·난수·최종 아트는 아직 남았다.

## 2026-10-27 — 0.6.0 로컬 저장·이어하기

단일 로컬 슬롯의 자동 저장과 자동 이어하기를 구현했다. 전투·보상 판정은 복사본을 끝까지 계산한 후 최종 상태를 먼저 저장하고, 저장 성공 시에만 한 번 커밋해 기존 Action Queue로 재생한다. 배치·보관·되돌리기도 `BattleSession`에서 복사본 저장 성공 후 적용한다. 저장 형식·복구 정책은 [저장 시스템](save-system.md)에 있다.

- 길목·턴·체력·기력·적·사용 횟수, 보상 후보·선택·확정 상태, 인스턴스 ID·좌표·회전·보관 순서와 되돌리기 이력을 저장한다. 현재 난수와 저장 마이그레이션은 없다.
- 연출 중 종료해도 마지막으로 확정된 상태를 직접 표시한다. 이전 명령·연쇄·보상을 다시 판정하거나 재생하지 않는다. 저장 실패 시 게임 상태·비용·배치·이력을 유지한다.
- 체크섬·버전·콘텐츠 해시·아이템 참조·보상 단계·배치 경계·겹침을 검사한다. 주 파일이 손상되면 이전 정상본을 사용하고 최근 행동 누락 가능성을 알린다. 손상 원본은 다음 저장 시 따로 보관한다.
- 콘텐츠가 달라졌거나 두 파일이 손상되면 자동으로 덮어쓰지 않는다. 사용자가 선택하면 주 저장과 이전 정상본을 보관하고 새 런을 시작한다. 다른 실행이 저장을 변경한 경우 충돌을 감지해 해당 행동을 거절한다.
- 파일 처리 잠금은 다른 실행의 잠금을 자동으로 제거하지 않는다. 저장 도중 강제 종료로 빈 잠금 폴더가 남으면 모든 게임을 종료한 뒤 수동으로 제거해야 한다. 저장 내구성은 운영체제와 파일 시스템의 제약을 받는다.

검증: 콘텐츠 53개·기존 규칙 99개·연쇄 22개·재생 24개·보상 61개·저장 123개, 총 **382개 실패 0**. 기존 UI·보상 UI·저장 UI, 잘못된 콘텐츠 가져오기 보호, 서로 다른 두 프로세스에서 전투 연출 중 저장·복원, release PCK의 두 프로세스 저장·복원도 통과했다. 테스트는 격리된 `build/` 경로를 사용했다. Windows 실기기의 저장 경로·파일 교체·권한은 아직 미검증이다.

전달 파일: `build/JeoseungBundle-prototype-0.6.0-windows.zip`, `build/source-snapshot-0.6.0-2026-10-27.zip`. M4의 로컬 저장을 선행 구현했지만 경로·사연·난수 진행은 남아 있다. M2 외부 플레이 관찰과 M3 픽셀 아트 기준 확정도 별도다.

## 2026-10-27 — 0.5.0 전투 보상·재배치

첫 두 전투 후 보상 후보 3개 중 하나를 고르고 시험 배치·확정한 뒤 다음 전투로 이동하는 흐름을 구현했다. 아이템 정의 12종·적 3종은 유지한다. 초기 지급은 7개로 조정하고, 나머지 기존 도구는 길목별 보상으로 만나도록 구성했다. [보상 흐름](reward-flow.md)에 데이터·상태·조작 계약을 정리했다.

- 후보 변경·건너뛰기는 시험 중인 보상만 제거하며 기존 장비의 재배치를 유지한다. 확정 전 배치·회전·되돌리기를 지원하고, 보따리에 넣어야 확정할 수 있다. 같은 후보를 다시 누르면 현재 시험 인스턴스를 재선택한다.
- `RewardRules`는 순수 값 트랜잭션을 반환한다. 보상도 `BattleSession.submit()`과 원자적 커밋·Action Queue를 거치며 UI에서 물건을 지급하지 않는다.
- 승리 연출 전 후보 노출, 전투 중 선택, 미배치 확정, 중복 확정, 이전 길목 요청을 거절한다. 후보 전환·확정·건너뛰기에서 배치 이력을 비워 이전 보상을 복구할 수 없게 한다.
- 보상 단계는 하단 전투 무대를 세 후보 카드로 바꾸고 상단 보따리·보관대·우측 상세와 확정 버튼을 유지한다. 확정 후 다음 전투에서도 획득 인스턴스를 정상 사용한다.
- 스키마 2에 `rewards.csv`를 추가했다. 템플릿은 8개 탭으로 갱신했다. 기존 고정 테스트 픽스처는 스키마 필드만 이전하고 수치는 바꾸지 않았다.

검증: 콘텐츠 53개·기존 규칙 99개·연쇄 22개·재생 24개·보상 61개, 총 **259개 실패 0**. 기존 UI와 새 보상 UI 통합 검사, 잘못된 가져오기 시 기존 파일 보존, release PCK 데이터 로드 검사를 통과했다. 초기 7개로 시작해 실제 전투 계산 3회와 보상 확정 2회를 거쳐 완주하는 고정 픽스처 검사를 포함한다. 3개 해상도에서 카드·상세·확정·건너뛰기의 경계와 보상 인스턴스 드래그를 확인했다.

macOS Godot 실제 렌더러로 출시용 데이터의 첫 전투를 진행하고, 오라 보상을 회전·배치해 봉인부 보너스 공격 6이 표시되는 화면을 확인했다. 이는 자동 입력·렌더 검증이며 Windows 실기기나 외부 플레이 관찰을 대신하지 않는다. 이미지: `build/reward-screen.png`. 템플릿의 계산된 CSV는 실제 로더와 일치했고 기존 5개 콘텐츠 탭의 값·수식 보존도 확인했다. Google Sheets 계정 업로드·네이티브 재계산은 수행하지 않았다.

전달 파일: `build/JeoseungBundle-prototype-0.5.0-windows.zip`, `build/source-snapshot-0.5.0-2026-10-27.zip`, 갱신된 `outputs/data-driven-content/balance-template.xlsx`. M4 중 보상·재배치를 완료했으며 경로·저장·사연은 남아 있다. 후보는 고정이며 난수 추첨, 판매·폐기, 보관대 용량 제한은 아직 없다. M2 외부 관찰과 M3 아트 기준 확정도 별도 진행한다.

## 2026-10-27 — 0.4.0 데이터 기반 콘텐츠

아이템별 코드 분기를 제거하고 `CSV/JSON → ContentLoader → ItemData/EffectUnit → EffectApplier` 흐름으로 전환했다. 기존 아이템 12종·적 3종·수치·배치를 유지하며, 조합 가능한 효과와 Google Sheets 가져오기용 밸런싱 템플릿을 제공한다. 사용 절차와 효과 계약은 [데이터 파이프라인](data-pipeline.md)에 있다.

- `ItemData`, `EffectUnit`은 필드만 가진 Resource다. 회전·스냅샷 변환·효과 계산·UI 표현은 각각 별도 계층이 소유한다. 런타임에서 특정 아이템 ID나 태그를 조건으로 쓰지 않는다.
- 효과는 발동 시점·연산·대상·인접 태그·횟수·중첩 그룹·우선순위로 조립한다. 비용은 사용 요청당 한 번 지불한다. 적 의도와 반응, 런 기본 수치와 초기 지급도 데이터로 옮겼다.
- CSV와 JSON은 동일 스키마·참조 검사를 거친다. 실패한 가져오기는 기존 파일을 보존하고, 게임 재시작의 로드 실패도 기존 세션을 보존한다. 실행 중 전투에 새 콘텐츠를 섞지 않는다.
- 판정 복사본·FIFO·원인 ID·단일 커밋과 기존 Action Queue를 유지한다. 장착·보관·소모 상태에 따라 반응 출처를 수집하며, 효과 계획과 연쇄 모두 상한을 둔다.
- UI 설명·대상·효과 수치는 데이터와 공통 계산으로 만들고, 긴 복합 효과 카드는 스크롤한다. 아이콘·캐릭터의 기존 픽셀 사각형도 데이터로 이관했다.
- 회귀 테스트는 고정 `tests/fixtures/baseline.json`을 사용한다. 출시 수치 조정과 규칙 회귀 검증을 분리했다. 반사·반응 방어·추가 500개 정의는 테스트 전용이며 출시 콘텐츠를 늘리지 않았다.

검증: `bash scripts/export-windows.sh`에서 필수 `bash scripts/check.sh` 전체 실행. 콘텐츠 **53개**, 기존 규칙 **99개**, 연쇄 **22개**, 재생 **24개**, 총 **198개 실패 0**. 구조 경계, UI 통합, 잘못된 입력의 기존 JSON 보존, 실제 release PCK의 데이터·메인 장면 로드도 통과했다. PCK 검사는 소스가 없는 작업 폴더에서 실행하고 테스트 픽스처가 패키지에 들어가지 않은 것도 확인한다. 0값 방어 설정의 턴 종료·피해 반응과 복합 효과의 FIFO 순서를 포함한다.

## 2026-10-27 — 0.2.0 판정·재생 분리

전투 입력은 `BattleSession.submit()`으로 모으고, 순수 판정 → 성공 결과의 단일 커밋 → Action Queue 재생으로 분리했다. 구현과 macOS 조작 확인은 10월 26일에 진행했으며, 중단 이후 27일에 결과와 전달 파일을 정리했다. 자세한 계약과 확장 규칙은 [전투 아키텍처](combat-architecture.md)에 있다.

- 판정기는 값 스냅샷에서 인접 보너스·타격·반응·소모·승패까지 계산하고 원인 ID와 단계별 상태를 기록한다.

- 재생 중 중복 입력과 배치를 잠근다. 건너뛰기·완료 시간 초과는 이미 확정한 상태로 화면을 맞추며 판정을 반복하지 않는다.

- `AGENTS.md`와 구조 경계 검사를 추가해 후속 작업에서 UI·연출에 판정과 await가 섞이는 실수를 감지한다.

## 발견하고 수정한 문제

1. `Control.rotation`과 아이템 회전 변수의 이름 충돌: 아이템 미리보기는 `pending_rotation`으로 분리했다.
2. 드래그에서 OS 포인터에 의존해 입력 이벤트와 좌표가 어긋나는 문제: 이벤트 좌표와 캔버스 변환을 사용하고 회귀 검사를 추가했다. 실제 창에서 재확인했다.
3. 부적 이동 미리보기가 선택한 부적만 계산하던 문제: 영향을 받는 검 공격과 가호 변화도 표시한다.
4. 모든 물건을 보관대로 옮겼을 때 공간이 늘어나는 문제: 보관대를 스크롤 영역으로 고정했다.
5. 가변 글꼴이 너무 가늘게 표시되는 문제: OpenType weight 축을 정수 태그로 지정하고 실제 화면에서 굵기를 확인했다. [Godot FontVariation 문서](https://docs.godotengine.org/en/stable/classes/class_fontvariation.html)
6. 마지막 전투 뒤 안내가 다음 길목을 가리키던 문제: 연습 완료 메시지로 수정했다.
7. release에서 `assert` 안의 초기화가 생략될 위험: 아이템 추가를 먼저 실행하고 결과만 검증한다.
