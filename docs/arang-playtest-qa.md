# 아랑 스테이지 플레이 점검

## 범위와 환경

- macOS Apple M3 Pro, Godot 4.7.2, 1280×720 기본 창에서 실제 마우스로 조작했다. 별도 테스트 슬롯을 사용했다.
- 스토리 안내를 읽고 클릭·드래그를 수행했지만 도구 관찰과 분석 사이 대기 시간이 섞여 있다. 이 기록으로 실제 플레이 시간을 산정하지 않는다.
- 개발 중인 에이전트의 내부 점검이다. 처음 접한 외부 플레이어의 이해도·재미 평가, Windows 실기기 및 출시 빌드 검증은 포함하지 않는다.

## 직접 플레이

| 경로 | 확인한 흐름 |
|---|---|
| 대숲·대화 | 시작 화면 → 기본 배치로 포졸 전투 2턴 → 짚신 보상 선택·배치·확정 → 동경을 보관대에 확보 → 대숲 선택 → 동경을 보따리에 배치 → 아랑 등장 → 동경을 보여 주고 듣기 → 결말 스크롤·완료 |
| 연못·전투 | 새 런 → 봉인부 이동으로 검의 피해 12→16 확인 → 포졸 전투 1턴 → 보상 건너뛰기 → 동경을 두고 감 → 연못 선택 → 한기 비용과 피격 반격 확인 → 아랑 전투 2턴 → 전투 결말 → 종료·재실행 → 결말 복원·완료 |

첫 번째 경로에서 턴 종료 미리보기의 방어 5와 실제 방어 결과가 일치했다. 두 번째 경로에서 검 피해 16과 아랑의 행동당 반격 2, 한기에 의한 검 사용 기력 증가를 확인했다. 이야기 스크롤과 보상·동경 선택이 마우스로 동작했다. 두 경로 모두 완료까지 진행했으며, 별도 저장을 종료 후 다시 열었을 때 직전 전투 결말을 재실행 없이 표시했다.

## 발견과 수정

- 동경 사건에서 아직 아무 선택도 하지 않았는데 주 버튼이 보따리에 넣으라고 표시했다. 선택 전에는 아래 선택지를 고르도록, 동경 선택 후에는 보관 가능 여부에 맞게 안내한다.
- 동경을 두고 온 뒤에도 준비 화면에서 동경을 휴대하라고 안내하고 전투 중 비활성 버튼에서 보따리에 넣으라고 했다. 남겨 둔 동경, 보관 중인 동경, 휴대한 동경을 구분해 표시한다.
- 첫 전투 후 승리 안내가 좁은 영역에서 잘렸다. 더 짧은 문구와 승리 상태 제목으로 교체했다.

## 남은 관찰 과제

- 대화 결말은 동경을 보따리에 넣었다면 아랑 등장 직후 선택할 수 있어 보스전이 짧게 끝난다. 몰입이나 난이도에 문제가 되는지는 외부 플레이어에게 확인해야 한다.
- 사건·결말 전문이 스크롤 영역에 있다. 실제 플레이어가 끝까지 읽는지 관찰해야 한다.
- 두 대면으로 충분한 길이인지, 두 경로와 결말이 재도전을 유도하는지는 내부 검증만으로 판단할 수 없다.
- `stage_one_ui_tests.gd`는 두 경로와 동경 휴대·보관·포기, 대화·전투 결말, 저장 복구를 자동 검사한다. 자동 검사는 실기기 조작과 사용자 관찰을 대체하지 않는다.
