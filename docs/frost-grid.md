# 원혼의 한기 — 아랑 대면의 칸 제약

아랑을 만나기 전 보따리를 정리하는 단계부터 위쪽 다섯 칸에 한기가 표시된다. `weapon` 태그가 있는 사용형 물건이 한기 칸을 한 칸 이상 차지하면 해당 물건의 사용 기력이 **행동당 한 번** 데이터에 정의된 만큼 증가한다. 현재 값은 +1이다. 여러 한기 칸에 동시에 닿아도 중복해서 증가하지 않는다. 비대상 아이템과 보관대 아이템에는 추가 비용이 없다.

5×4 보따리에서 외곽 전체를 막으면 1×3 세로 검이 어디에도 완전히 들어갈 수 없다. 따라서 첫 버전은 위쪽 한 줄만 얼린다. 검을 가로로 회전해 안쪽에 배치할 수 있지만, 기존 물건을 옮겨 공간을 만들어야 한다. 전투 중 재배치는 지원하지 않으므로 대면 **전**에 표시·결정한다. 두 아랑 경로에 동일하게 적용되며, 대면 결과가 나오면 표시와 비용 증가가 사라진다. 전투 중 한기 확산·피격 시 생성·무작위 칸 이동은 아직 없다.

## 표시와 판정

서리빛 나뭇가지 선과 작은 눈송이는 영향 칸을 뜻한다. 처음 나타날 때 해당 이벤트의 재생으로 테두리에서 자라며, 복원하거나 건너뛰면 완성된 상태를 바로 표시한다. 물건의 기력 배지는 현재 비용을 표시하고, 한기로 증가한 숫자는 파란색이다. 오른쪽 상세 정보는 실제 비용과 증가 원인을 표시한다. 배치·회전 미리보기는 예상 배치의 비용을 보여 주며, 변경되는 경우 안내 문구에 전후 비용을 표시한다. 하단과 길잡이는 대상 태그와 증가량을 데이터에서 생성한다.

`InventoryRules.active_hazards()`와 `action_cost()`는 표시 스냅샷 및 값 데이터로 동일한 비용을 계산한다. 실제 사용 요청은 `BattleSession.submit()`을 거쳐 복사본에서 비용 검사와 효과를 계산하고, 저장 성공 후 커밋·재생한다. `action_started` 이벤트는 기본 비용·추가 비용·실제 비용을 기록한다. 현재 기력이 부족하거나 한기로 인해 매 턴 어떤 공격도 쓸 수 없는 배치에서는 전투 시작을 거부해 전투 중 배치 잠금에 갇히지 않게 한다. 전투 종료 예측은 기존과 동일한 순수 판정기를 사용한다.

한기 칸은 진행 단계와 검증된 콘텐츠에서 결정적으로 파생된다. 가변 칸 상태·타이머·난수는 추가하지 않았으므로 별도 저장 필드나 연출 재실행이 없다. 콘텐츠 해시에는 한기 데이터가 포함된다. 0.14 저장은 내용이 달라 자동 혼합하지 않고, 사용자가 보관 후 새로 시작하도록 기존 복구 창을 제공한다.

## 콘텐츠

`content/source/hazards.csv`와 Google Sheets 템플릿의 `hazards` 탭에서 `id`, `step`(0부터 시작), 절대 좌표 `cells`(예: `0:0|1:0`), `required_tags`, `cost_increase`, `label`, `description`을 편집한다. 좌표 중복·범위 밖·없는 태그·동일 단계의 중복 행·잘못된 비용을 거부한다. CSV는 기능을 쓰지 않아도 헤더가 필요하고 JSON은 빈 배열이나 필드 생략을 허용한다. 현재 엔진은 **각 단계에 최대 한 행**, 고정 위치, 태그 전체 일치, 비용 증가만 지원한다. 수치를 바꾸면 안내의 태그·비용도 함께 갱신되며 설명란에는 수치를 중복 기재하지 않는다.

`hazard_tests.gd`는 동일한 판정의 미리보기·실제 비용, 여러 칸 중복 방지, 비대상 아이템, 기력 부족·전투 시작 보호, 저장 충돌·연출 중 복원, 배치·회전·되돌리기 및 이전 콘텐츠 저장 보존을 검사한다. `stage_one_ui_tests.gd`는 실제 출시 데이터의 양쪽 경로·증거 선택·퇴치/해원 완주를 계속 검사한다. 실제 사용자 플레이 관찰과 Windows 실기기 검증은 남았다.
