# 0.10.0 런 저장과 이어하기

시작 화면에서 진행을 선택하면 단일 로컬 저장 슬롯을 검사하고 마지막으로 확정된 런을 이어간다. 저장이 없으면 첫 인도 상태를 새로 기록한다. 시작 화면은 주 파일이나 백업의 존재만 확인하며 저장 내용을 읽어 덮어쓰지 않는다. 저장 위치는 `user://saves/run.json`이다. `user://`는 운영체제별 Godot 사용자 데이터 폴더이므로 저장소·설치 폴더에 진행 파일을 쓰지 않는다. Steam Cloud와 여러 저장 슬롯은 아직 없다. [Godot 파일 경로 문서](https://docs.godotengine.org/en/stable/tutorials/io/data_paths.html)

## 무엇을 저장하는가

저장 포맷 버전, 검증한 콘텐츠의 SHA-256, 선택한 경로와 단계, 유품 사건의 임시·확정 선택과 후속 결과, 길목·전투 단계·턴·체력·기력·방어·적 체력·사용 횟수·전투 기록, 보상 후보·선택·처리 상태, 아이템 정의와 인스턴스 ID·좌표·회전·보관 순서, 배치 되돌리기 이력을 저장한다. 현재 콘텐츠에 난수는 없으므로 난수 상태는 아직 없다. 나중에 난수나 다른 런 상태를 도입할 때 저장 포맷과 검증을 함께 확장해야 한다.

파일에는 상태 값만 기록하며 코드·Callable·Resource 객체를 불러와 실행하지 않는다. 재시작 때 현재 검증된 카탈로그에서 정의와 설정을 다시 구성하고, 아이템 참조·보상 단계·좌표·겹침·이력·수치 범위를 확인한다. 사용 후 사라진 소모품의 사용 횟수도 같은 턴 동안 보존한다. 표시용 Tween·대기열은 저장하지 않는다.

## 커밋과 재생의 순서

전투와 보상 요청은 `BattleSession.submit()` → 순수 판정 → **최종 결과 저장** → 단일 커밋 → Action Queue 재생 순서다. 준비·보상 단계의 배치·꺼내기·되돌리기는 `BattleSession`이 복사본에 적용하고, 저장이 성공해야 원본 인벤토리를 바꾼다. UI는 표시 스냅샷을 사용하며 직접 저장하거나 아이템을 지급하지 않는다.

저장에 실패하면 요청 전체를 거절한다. 기력·체력·소모·보상·배치·되돌리기 이력과 화면 상태는 기존 값을 유지하며 오류를 표시한다. 임시 파일 교체가 성공한 직후 프로세스가 종료되면 커밋된 결과로 이어질 수 있다. 이전 행동을 다시 판정하거나 연출을 재생하지 않는다. 따라서 연출 중 강제 종료 후에는 마지막 결과가 바로 표시된다.

## 파일 교체·복구

같은 폴더의 임시 파일에 UTF-8 JSON을 쓰고 `flush()`한 뒤 이전 정상본 `run.json.bak`을 보관하고 주 파일을 이름 변경으로 교체한다. 각 내용에 체크섬을 넣고 읽기·쓰기 전에 검증한다. Godot의 파일 API는 오류를 반환하며, 실제 파일 시스템·정전 상황에 따른 내구성은 별도다. [FileAccess](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html), [DirAccess](https://docs.godotengine.org/en/stable/classes/class_diraccess.html)

- 주 저장이 손상되고 이전 정상본이 유효하면 이전 정상본을 불러오고 **최근 행동이 누락될 수 있음**을 알린다. 읽기만 할 때는 손상 원본을 바꾸지 않는다. 다음 저장 시 손상 원본을 `run.json.damaged-<SHA-256>`으로 따로 보관한다.
- 두 파일 모두 읽을 수 없거나 버전·콘텐츠가 다르면 진행을 잠그고 기존 파일을 그대로 둔다. 플레이어가 **보관하고 새로 시작**을 선택한 경우에만 `saves/archive/`에 주 저장과 백업을 각각 내용 해시로 보관한 뒤 새 슬롯을 만든다. 확인을 닫으면 원본은 변하지 않는다.
- 다른 실행이 같은 슬롯을 수정한 경우 오래된 실행은 덮어쓰지 못하고 다시 열도록 안내한다. 파일 처리 중에는 빈 `run.json.lock` 폴더로 동시 접근을 막는다. 저장 작업 중 프로세스가 강제 종료되어 잠금이 남은 경우에는 **모든 게임을 종료한 뒤** 해당 빈 잠금 폴더를 수동으로 제거해야 한다. 자동으로 다른 프로세스의 잠금을 제거하지 않는다.
- 각 파일은 최대 8 MiB다. 체크섬은 우발적 손상 감지용이며 변조 방지나 암호화 기능이 아니다.

## 콘텐츠 변경과 호환성

해시는 아이템·효과·보상·초기 배치·적·시각 데이터 등 검증된 카탈로그 전체를 기준으로 한다. Google Sheets/CSV를 가져와 어느 값이든 변경하면 기존 런을 자동 적용하지 않는다. 이전 파일을 해당 콘텐츠 버전과 함께 유지하거나 게임의 **보관하고 새로 시작**을 선택한다. 0.9.0 저장 포맷은 현재 카탈로그에서 events를 제거하고 스키마를 3으로 되돌린 해시가 기존 해시와 같을 때 이전한다. 이미 첫 사건 지점을 지나간 런은 진행을 되돌리지 않는다. 읽기만 할 때 원본은 유지하고 다음 정상 저장에서 이전 파일을 백업한다. 예외적으로 0.6.0 저장 포맷은 새 카탈로그에서 routes를 제거하고 스키마를 2로 되돌린 해시가 저장된 콘텐츠 해시와 정확히 같을 때 이전한다. 첫 길목 이후 진행 중인 런은 기존 0→1→2 순서를 유지하고, 첫 길목에서는 갈림길에서 직접 선택한다. 읽기만 할 때 기존 파일을 덮어쓰지 않으며 다음 정상 저장 시 이전 파일을 백업한다. 기존 콘텐츠가 다른 경우에는 이전하지 않는다.

런 중 데이터를 다시 가져와도 이미 시작한 런의 설정은 바뀌지 않는다. 새 콘텐츠는 다음 게임 실행이나 새 런에서 읽는다. 버전이 다른 파일은 더 오래된 백업으로 조용히 대체하지 않는다.

대각선 범위 지원은 기존 카탈로그나 저장 데이터 자체를 바꾸지 않는 스키마 허용 값 확장이다. 기존 콘텐츠로 만든 저장은 동일한 해시를 사용한다. 새 범위를 실제 콘텐츠에 작성하면 카탈로그 해시가 달라지므로 위의 콘텐츠 불일치 보존 정책이 적용된다.

정수 배율 지원도 기존 카탈로그와 저장 포맷을 바꾸지 않는다. 배율 결과와 누적 방어는 저장의 정확한 정수 범위를 초과하지 않도록 판정 중 검사하며, 초과하면 결과를 저장하거나 커밋하지 않는다. 새 배율을 출시 콘텐츠에 작성하면 카탈로그 해시가 바뀐다.

## 검증 범위

`bash scripts/check.sh`는 전투 연출 중 저장, 소모품 제거, 보상 선택·변경·확정·건너뛰기, 배치·회전·되돌리기, 새 런 시작, 디스크 쓰기·교체 실패, 손상·버전 불일치·잘못된 상태, 이전 정상본, 동시 실행 충돌을 검사한다. 게임 화면을 닫고 다시 생성하는 UI 검사와 별도 프로세스 두 개에서 저장·복원을 확인하는 검사도 실행한다. 모든 테스트는 `build/`의 격리 슬롯을 사용하며 실제 사용자 저장을 건드리지 않는다.

`bash scripts/export-windows.sh`는 release PCK에서도 별도 프로세스 저장·복원 검사를 실행한다. 이는 macOS에서 생성한 Windows 빌드의 데이터·코드 검증이며 Windows 실기기의 파일 권한·교체 동작 검증을 대신하지 않는다.


## 사건 결말 저장 (버전 4)

결말 데이터가 있는 런은 증거를 보관대에 둔 선택, 전투 중 결말 요청, 퇴치·해원 결과와 조기 완료를 저장·검증한다. 해원 결과는 지정 사건·휴대 유품·길목·결과 단계가 맞는지 확인한다. 판정 결과를 먼저 저장하고 그 뒤에만 확정·재생하며, 연출 중 종료 후에는 재판정 없이 결과 화면부터 복원한다. 일반 런의 버전 3 저장은 콘텐츠 해시가 같으면 읽기 전용으로 버전 4에 이전하고 다음 정상 저장 때 기존 원본을 백업한다. 내용이 다르면 원본을 보존한다. 시연은 기본 저장이 꺼져 있고 선택적으로 본편과 다른 슬롯을 쓴다.


0.14.0 아랑 스테이지는 콘텐츠 자체가 달라 0.13의 저장 해시와 일치하지 않는다. 자동 이전하지 않고 복구 창에서 기존 저장을 보존한다. 명시적인 보관 후 새 런을 시작할 수 있으며, 자동 혼합이나 원본 덮어쓰기는 하지 않는다. [스테이지 안내](arang-stage-one.md)


0.15.0의 한기 행은 콘텐츠 해시에 포함되므로 0.14 저장은 자동 혼합하지 않는다. 기존 파일을 보존하고 명시적인 보관 후 새 런을 시작할 수 있다. 한기 위치는 저장한 경로 단계와 현재 콘텐츠에서 결정되며 별도 가변 저장 필드가 없다. [원혼의 한기](frost-grid.md)


0.16.0은 아이템 효과와 적 데이터를 바꾸므로 0.15.0 저장과 콘텐츠 해시가 다르다. 기존 파일을 자동으로 덮어쓰거나 혼합하지 않으며, 안내에 따라 파일을 보관한 후 새 런을 시작한다.


0.21.0은 콘텐츠 텍스트를 영어로 바꾸고 첫 보상 후보를 조정하므로 0.20.0 카탈로그와 해시가 다르다. 이전 저장은 호환되지 않는 것으로 안내하고 원본을 보존하며, 명시적인 보관 후 새 런을 시작할 수 있다. 사용자 저장을 자동 삭제하거나 덮어쓰지 않는다. 기존 Godot 프로젝트 식별자는 유지하고 창 제목만 영어로 표시해 이전 `user://` 경로를 계속 찾는다.


0.21.1의 별도 아랑 시연은 기존 시연 카탈로그 해시와 저장 슬롯을 유지한다. 영문 표시 자료는 이름과 대사만 화면에서 바꾸며 판정 수치를 수정하지 않는다. 이전에 저장된 한글 전투 기록은 화면에서 영문 대체 문구로만 표시하며, 저장 파일이나 기존 기록을 읽기만 할 때 변경하지 않는다. 시연과 본편은 별도 슬롯이다. [아랑 시연 안내](arang-experiment.md)
