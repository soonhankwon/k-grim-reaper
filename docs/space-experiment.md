# 1×4 대검 공간 실험

## 목적

강한 무기를 얻었을 때 기존 배치를 유지할지, 기존 물건을 빼거나 옮겨 새 조합을 만들지 관찰한다. 이는 밸런스와 재미를 **검증하기 위한 테스트 픽스처**다. 출시 아이템 종류·적·에셋과 기존 고정 밸런스는 바꾸지 않았다. 플레이 결과가 좋다는 결론은 아직 없다.

## 실행

macOS/Linux에서 Godot 4.7.2를 설치한 뒤 저장소 루트에서 실행한다.

```bash
bash scripts/run-space-experiment.sh
```

Godot 실행 경로가 다르면 `GODOT_BIN='/설치/경로/Godot' bash scripts/run-space-experiment.sh`를 사용한다. Windows에서 소스와 같은 버전의 Godot 실행 파일이 있다면 프로젝트 루트에서 `Godot.exe --path game --script res://tests/space_experiment_launcher.gd`를 실행한다. Windows 명령과 실기기 실행은 아직 검증하지 않았다.

상단에 **공간 실험 · 저장 안 함**이 표시된다. 테스트는 메모리에서만 진행하며 기존 사용자 저장을 읽거나 쓰지 않는다. 게임을 닫으면 진행은 사라지고, 다시 시작하면 실험 배치가 초기화된다. 정식 Windows ZIP은 테스트 픽스처와 실험 모드를 포함하지 않는다.

## 실험 구성

- 평소와 같은 초기 보따리·일곱 물건·적 세 명에 더해, 보관대에 테스트용 **실험용 대검** 하나가 있다.
- 세로 1×4칸, 기력 2, 턴당 1회, 기본 공격 13이다. 무기 태그가 있어 기존 봉인부 조건에 따라 공격이 달라질 수 있다. 그림은 기존 검 시안을 재사용한다.
- 현재 초기 배치에서는 회전해도 대검을 바로 넣을 수 없다. 한 물건 이상을 옮기거나 꺼내야 하며, 겹치는 배치는 확정되지 않는다.
- 효과는 일반 아이템과 같은 데이터 스키마·공통 효과 엔진을 사용한다. 실험용 정의는 `game/tests/fixtures/space-experiment.json`에만 있다. 기존 CSV/JSON 출시 카탈로그와 사용자 저장을 변경하지 않는다.

## 관찰 방법

외부 플레이어가 가능하다면, 다음 안내만 주고 특정 배치의 정답은 알려 주지 않는다.

> 보관대의 실험용 대검을 살펴보고, 이 무기를 쓸지 결정하세요. 보따리를 원하는 대로 정리한 뒤 첫 전투를 진행해 주세요.

| 관찰 항목 | 기록 |
|---|---|
| 플레이어 / 날짜 / 빌드 | |
| 대검을 넣었는가, 쓰지 않기로 했는가 | |
| 옮기거나 꺼낸 물건과 그 이유 | |
| 첫 배치를 바꾸는 데 걸린 시간과 막힌 지점 | |
| 대검의 칸 수·기력·공격력을 이해했는가 | |
| 기존 시너지를 유지하거나 포기한 이유를 설명했는가 | |
| 배치 전 예측과 첫 전투 결과가 같다고 이해했는가 | |
| 다시 배치해 보고 싶은가 / 반복 정리가 피곤한가 | |

관찰자는 적어도 두 개의 선택이 실제로 가능한지 별도로 확인한다. 자동 검사에서는 기존 검을 보관대로 옮겨 대검을 넣는 배치와, 방울을 꺼내고 반지·부적을 옮겨 두 검을 함께 넣는 배치를 검사한다. 이 예시는 관찰 시작 전에 플레이어에게 알려 주지 않는다. 한 배치의 승리나 자동 검사는 재미·균형의 증거가 아니다.

## 자동 검증

`space_experiment_tests.gd`는 출시 카탈로그와 픽스처의 차이를 테스트용 아이템·효과·인스턴스 한 개로 제한한다. 초기의 모든 좌표·네 방향에서 배치가 불가능한지, 회전과 겹침 처리, 두 대안의 미리보기와 실제 전투 결과, 저장 서비스 비활성화, 드래그·재시작·창 크기를 검사한다. `bash scripts/check.sh`에 포함된다. `--capture`를 붙인 테스트는 별도 실제 렌더 화면을 만든다.
